# 日次ファクトリー：毎日1本作り、数字で判定し、伸びているものを更新する

方針（2026-11-11）：1本に賭けず、小さいゲームを毎日1本以上出して、数字が良いものだけを育てる。
判定は人の気分ではなく `rules.json` のルールで行う。

## 毎日の流れ（Claude が実行する。`roblox-daily-factory` スキル）

| 順 | やること | コマンド | 自動か |
|---|---|---|---|
| 1 | 公開中の全ゲームの数字を取る | `python tools/factory/factory.py metrics` | 自動（API キーが要る） |
| 2 | ルールで判定し、今日の作業リストを出す | `python tools/factory/factory.py decide` | 自動 |
| 3 | 【更新】伸びているもの（最大3本）に新要素を1つ足して公開する | 実装 → `publish <slug>` | 自動 |
| 4 | 【改善】中間のものは「最初の5分」を直す（3回まで） | 実装 → `publish <slug>` | 自動 |
| 5 | 【終了】基準に届かないものを非公開にする | Creator Hub | **人** |
| 6 | 【新作】ネタ帳の先頭を1本作る | `next` → 実装 → `tools/check.sh` → `add <slug>` | 自動 |
| 7 | 新作を空きスロットに公開し、サーバー上で起動テストをする | `publish <slug>` → `smoke <slug>` | 自動（スロットと、キーの Luau 実行権限が要る） |
| 8 | 新作を「公開」に切り替える（成熟度アンケート、サムネイル） | Creator Hub | **人（1本あたり数分）** |
| 9 | レポートを書いて commit / push する | `report` | 自動 |

時間の配分は「伸びているものの更新が先、新作が後」。伸びているものが3本あるあいだも、新作は1日1本を守る。

## 判定ルール（`rules.json`）

| 判定 | 条件 | 次にやること |
|---|---|---|
| BUILD_ONLY | まだ公開していない | スロットを割り当てて公開する |
| WAIT | 遊んだ人が100人未満 | 待つ。数字が少なすぎて判定できない |
| NO_TRAFFIC | 公開から7日たっても100人未満 | サムネイルと題名を作り直す（1回だけ）。少額広告も検討する |
| ARCHIVE | 作り直しても人が来ない | 非公開にしてスロットを空ける |
| SCALE | 「D1 20%以上」「D7 7%以上」「セッション12分以上」のうち2つ以上 | 毎日1つ新要素を足す。上位3本まで |
| HOLD | SCALE だが4位以下 | 維持だけする |
| ITERATE | SCALE でも KILL でもない | 最初の5分を直す。3回で届かなければ KILL |
| KILL | 「D1 10%未満」「セッション5分未満」「60秒以内の離脱60%超」のうち2つ以上 | 非公開にする。学びを CHANGELOG に1行残す |

判定のしきい値は、`roblox-game-concept` スキルの「続けるか撤退するかの判断」と同じ。
ルールを変えたら `python tools/factory/factory.py selftest` を回す（10ケース＋上位3本の制限を検査する）。

## ファイル

| ファイル | 中身 |
|---|---|
| `backlog.json` | ネタ帳。上から順に作る。`status` は todo → built |
| `portfolio.json` | 台帳。ゲームごとの段階、ID、日ごとの数字、判定の履歴 |
| `slots.json` | 先に作っておく空の体験の一覧（`universeId` と `placeId`） |
| `rules.json` | 判定のしきい値 |
| `reports/<日付>.md` | 日次レポート |

## 人がやること（機械にできない部分）

1. **API キーを発行する（1回だけ）。** Creator Dashboard で作り、リポジトリ直下の `.env` に `ROBLOX_API_KEY=...` と書く（`.env` は git 管理外）。
   - 権限：`universe-places` の Write（公開）、`universe-analytics` の `universe.analytics:read`（数字）。
   - 対象の体験を追加する。スロットを増やすたびに、キーの対象にも足す。
2. **空の体験（スロット）をまとめて作る。** 新しい体験は API では作れない。Creator Hub か Studio で空の体験を10個ほど作り、`slots.json` に書く。
   ```json
   [{ "universeId": 1234567890, "placeId": 9876543210, "slug": null }]
   ```
3. **新作を「公開」に切り替える。** 成熟度アンケートに答え、アイコンとサムネイルを入れる。切り替えたら Claude に伝える（`publish <slug> --public` で公開日を記録する）。
4. **終了になったゲームを非公開にする。**

## 守ること（量産で失敗しないために）

- **毎日ちがう遊びにする。** 見た目だけ変えた色違いは出さない。ほぼ同じメタデータの作品は、おすすめで優先されない【確定：research/01】。大量の似たゲームは、スパムとして扱われるおそれがある。
- **1日で作る範囲は「1つのルール＋5分遊べる中身」まで。** 伸びたら足す。
- **`tools/check.sh` が通らないものは公開しない。**
- 法務チェック（`reports/future_games_plan.md` §2-5）を新作ごとに通す。実在のブランド、他作品の名前・見た目は使わない。
- 有料ガチャは確率表示と PolicyService の制限を必ず入れる（テンプレートに実装済み）。
- 新作には最初は人がほとんど来ない。数字が100人に届かないゲームは判定しない。早く判定したいときは少額広告を使う（予算はユーザーが決める）。

## 自動実行

Claude Code のスケジュール機能で、毎日決まった時刻に「`roblox-daily-factory` スキルを実行する」タスクを登録できる。
Roblox の API は PC からしか届かないので、PC 側のセッションで動かす（クラウドのコンテナは roblox.com に届かない）。
